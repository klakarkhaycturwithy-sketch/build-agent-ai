# Security, Copyright & Deployment Reference (Brief v2.0 ข้อ 8)

คู่มือตรวจความปลอดภัย ลิขสิทธิ์ และการส่งมอบงานประจำผู้ช่วยส่วนตัว `/nongton`

## 1. ด่านตรวจความปลอดภัยก่อน Commit / Push / Deploy
1. **ตรวจข้อมูลลับ (`HARD RULE 6`):** ห้ามฝัง API key, token, รหัสผ่าน หรือข้อมูลส่วนตัว/การเงินในโค้ดหรือ memory ห้ามแสดงในคำตอบ ให้ใช้ไฟล์ `.env` และบันทึกเฉพาะ "ชื่อตัวแปร"
2. **ตรวจโฟลเดอร์ทางลัด (`HARD RULE 8`):** ตรวจสอบว่า `.gitignore` และ `.vercelignore` ยกเว้นโฟลเดอร์ `Claude-AppData/`, `Gemini-*`, `.backups/`, `_archive/`, และ `_to_delete/` ครบถ้วน
3. **ขออนุมัติก่อนทำสิ่งที่มีผลกับโลกจริง (`HARD RULE 5`):** การส่งข้อความ/อีเมล, `deploy`, `git push`, เผยแพร่งาน หรือใช้จ่ายเงิน ต้องแสดงรายการและรอให้คุณ `nongton` อนุมัติก่อนทุกครั้ง

## 2. ด่านตรวจลิขสิทธิ์ (`HARD RULE 9`)
- ไม่ทำซ้ำเนื้อหาที่มีลิขสิทธิ์ของผู้อื่นตรงตัวโดยไม่มีสิทธิ์
- หากคุณ `nongton` ต้องการนำงานของผู้อื่นมาใช้ ให้ถามก่อนทุกครั้งและเสนอทางเลือกที่ถูกสิทธิ์: (ก) ใช้แหล่งที่ไลเซนส์อนุญาต (ข) สรุป/เรียบเรียงใหม่ด้วยคำของตัวเอง หรือ (ค) สร้างขึ้นใหม่ พร้อมบันทึกแหล่งที่มาลงใน `SOURCES.md`
