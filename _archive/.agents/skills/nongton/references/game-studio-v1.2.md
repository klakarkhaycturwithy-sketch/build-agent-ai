# Game Development Studio Reference (v1.2 — Roblox Luau + Rojo & Godot GDScript)

คู่มือความเชี่ยวชาญด้านการสร้างเกมที่ถูกเรียกใช้อัตโนมัติผ่านคำสั่ง `/nongton` ร่วมกับกฎหลักใน `.agents/rules/game-dev-*.md`

## 1. ความเชี่ยวชาญคู่ขนาน 2 เอนจินหลัก (Dual-Engine Mastery ที่คุณ nongton เลือกไว้)

เอเจนต์ `/nongton` รองรับการเขียนโค้ดและสอนใช้งานทั้ง 2 เอนจินหลัก (รวมถึงเว็บเกมเมื่อสั่งเฉพาะกิจ) โดยให้เลือกใช้ตามลักษณะโปรเจกต์ที่คุณ `nongton` สั่ง:

### เอนจิน A: Roblox Studio (ภาษา Luau) + เชื่อมโค้ดผ่าน Rojo
- **เหมาะสำหรับ:** เกมออนไลน์หลายผู้เล่น (Multiplayer Arena, PvP/Co-op), เกมที่ต้องการปล่อยสาธารณะให้คนเข้าเล่นง่ายและต่อยอดสร้างรายได้ (Robux / Gamepasses / Developer Products)
- **สถาปัตยกรรมมาตรฐาน (Rojo Project Structure):**
  - `default.project.json` — ไฟล์เชื่อมโฟลเดอร์ใน Antigravity เข้ากับ Roblox Studio
  - `src/server/` (`ServerScriptService`) — ตรรกะฝั่งเซิร์ฟเวอร์: ตรวจการยิงโดน (`Raycast`), คำนวณความเสียหาย, จัดการเงิน/ค่าหัว, ระบบเซฟ (`DataStoreService` พร้อมเลขเวอร์ชันและ `pcall` ป้องกันเซฟพัง)
  - `src/client/` (`StarterPlayerScripts`) — ตรรกะฝั่งผู้เล่น: กล้อง FPS, การซูมสโคป (`TweenService`), แรงดีดปืน (Recoil), เสียงและ HUD
  - `src/shared/` (`ReplicatedStorage`) — สัญญากลาง: ข้อมูลปืน (`WeaponConfig`), ชื่อ `RemoteEvent` / `RemoteFunction`, โมดูลใช้ร่วมกัน

### เอนจิน B: Godot Engine 4.x (ภาษา GDScript ใกล้เคียง Python)
- **เหมาะสำหรับ:** เกม 2D/3D แบบเป็นเจ้าของไฟล์เกม 100% (`.exe` / Web / Steam / itch.io), เกมแนว RPG / เอาชีวิตรอด / สู้ฝูงบอทและบอส (PvE) ที่รันลื่นไหลบนการ์ดจอ AMD Radeon RX Vega
- **สถาปัตยกรรมมาตรฐาน (Godot Scene & Script Structure):**
  - `project.godot` — ไฟล์ตั้งค่าโปรเจกต์ (ใช้ Renderer แบบ Compatibility หรือ Forward+ ที่เข้ากับ AMD RX Vega)
  - `scenes/` — แยกฉากตามหน้าที่ (`main_arena.tscn`, `player_fps.tscn`, `enemy_bot.tscn`, `hud.tscn`)
  - `scripts/autoload/` — ระบบกลาง (`GameState.gd`, `SaveManager.gd` ที่เซฟลงไฟล์ชั่วคราวก่อนเขียนทับเพื่อกันไฟล์เซฟเสีย)
  - `resources/` — ตารางค่าสถานะปืน ศัตรู และไอเท็ม (แยกข้อมูลออกจากโค้ดเพื่อปรับสมดุลง่าย)

## 2. กฎการตั้งต้นโปรเจกต์เกม (Concept Gate & Sniper Arena Preset)
1. **ตรวจสอบแนวเกมก่อนเสมอ:** ทุกครั้งที่เริ่มโปรเจกต์เกมใหม่ ให้ถามหรือดูคำสั่งของคุณ `nongton` ก่อนว่าต้องการสร้างเกมแนวไหน (ไม่บังคับว่าต้องเป็นเกมสไนเปอร์ หากต้องการทำแนวอื่น เช่น RPG ล้วน หรือเอาชีวิตรอดแนวอื่น ให้ปรับตามโจทย์ใหม่ทันที)
2. **ค่าตั้งต้นที่ยืนยันแล้วสำหรับโปรเจกต์ "สนามประลองสไนเปอร์" (Hybrid Sniper Arena):**
   - **มุมมองกล้อง:** FPS (บุคคลที่หนึ่ง เห็นมือและลำกล้องปืน ซูมสโคปเต็มตา)
   - **คำโปรยหลัก:** *"หลบให้พ้น เล็งให้แม่น และเป็นหนึ่งเดียวในสมรภูมิสไนเปอร์สุดเดือด!"*
   - **แกนคอนเซ็ปต์ผสมผสาน (Hybrid 1+2+3):**
     1. *Sniper Bounty Arena:* ยิงนัดเดียวจบ สะสมค่าหัว (`Bounty Streak`) ถอนตัวเพื่อเก็บเงินเข้าเซฟหรือเสี่ยงสู้ต่อเพื่อตัวคูณรางวัล
     2. *Sniper Hunter RPG:* มีบอทศัตรู/บอสให้ฟาร์มเลเวล ดรอปชิ้นส่วน และอัปเกรดปืน/สกิลทรีสไนเปอร์ (เล่นคนเดียวตอนไม่มีคนก็สนุกได้)
     3. *Shifting Arena Events:* สนามประลองมีเหตุการณ์เปลี่ยนสถานะทุก 60 วินาที เพื่อแก้ปัญหาคนนั่งแคมป์จุดเดิมและทำให้เล่นซ้ำได้นานไม่เบื่อ
   - **เป้าหมายปลายทาง (Public Release & Monetization):** ออกแบบรองรับการเปิดสาธารณะ (ข้อ C) และต่อยอดหารายได้ (ข้อ D) โดยแยกของสายเปย์ให้เป็นของตกแต่ง (Skins / เอฟเฟกต์ประกายแสงเมื่อสังหาร) หรือความสะดวกที่ไม่ทำให้เกมเสียสมดุลแบบ Pay-to-Win จนผู้เล่นใหม่หนี
